# 契約・月次明細・請求 データ整合性監査結果

> 更新情報: 2026-08-06に安全に一意確定できる527レコードを修正済み。最新結果は `outputs/data-integrity-fix-20260806/安全更新実施結果.md` を参照。本書の件数は修正前スナップショットである。

## 1. 監査概要

- 対象環境: Salesforce本番 `prod`
- 基準日: 2026-08-05
- 対象件数:
  - 契約管理: 237件（有効契約135件）
  - 契約期間: 384件
  - 契約月次明細: 2,052件
  - 請求: 413件
  - 請求明細: 495件
- 本監査ではデータ更新を行っていない。

初回機械監査では3,094件の指摘候補（2,302レコード）が検出された。ただし、1レコードに複数の指摘が付くほか、契約終了日空欄など現行設計上許容される可能性がある項目も含むため、件数をそのまま不正レコード数とは扱わない。

## 2. 結論

優先して対応すべきなのは、参照先が別契約・別取引先になっているレコード、当月月次明細の不足、請求未紐付け、MRR計上不能、重複月次明細である。特に、契約月次明細の関連請求を使って送付・決済ステータスを表示する設計のため、関連請求の誤紐付けは営業・経理双方のレポートを直接誤らせる。

## 4. 仕様上の確認が必要な項目

### 有効契約の契約終了日

有効契約135件のうち134件で契約終了日が空である。一方、契約期間オブジェクトで期間を管理する設計のため、直ちに不整合とは断定しない。契約管理の終了日を必須とするか、契約期間のみを正とするかをデータ定義として統一する必要がある。

### 年払い契約の関連請求

年払いでは1件の請求が12か月の月次明細に対応するため、請求月と月次明細月が離れること自体は正常である。675件は月払い・年払いを分類した上で、月払いだけを修正対象とする。

### 請求金額項目

INV-0000000011とINV-0000000045では、入金額が税抜の `InvoiceAmount__c` を上回り、税込相当になっている。freee同期で請求金額を税込として扱う現在の要件と、旧移行データの項目定義が混在している可能性がある。

## 5. 推奨対応順

1. P0の別契約・別取引先参照と請求明細欠落をバックアップ後に修正する。
2. 有効契約41件についてfreee請求の有無を照合し、未取込ならWorkへ再取得する。
3. 2026年8月月次明細がない42契約を、契約期間・商品・請求情報と照合して生成する。
4. 月次明細のMRR空欄219件と商品空欄1,405件を、確度別に自動補完・要確認へ分ける。
5. 月払いだけを対象に関連請求675件を再判定し、誤紐付けを解消する。
6. 重複19組は削除せず、請求・商品・金額を突合して正レコードを確定する。
7. URL、税額、請求対象期間を機械補完する。
