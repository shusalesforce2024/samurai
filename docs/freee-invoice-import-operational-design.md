# freee請求取得 通常運用設計

作成日: 2026-07-04

## 方針

通常運用のfreee請求取得は、前月分と今月分のみを対象にする。
全期間や広範囲の取得は、移行時または例外対応時の手動実行に限定する。

## 通常取得範囲

実行日を基準に、以下の期間を取得する。

| 項目 | 値 |
|---|---|
| 開始日 | 前月1日 |
| 終了日 | 当月末 |
| 取得単位 | 1日単位、ページングあり |
| 1ページ件数 | 10件 |
| ページ送り間隔 | 60分 |
| ページング方式 | `limit` / `offset` |

例:

| 実行日 | 取得対象 |
|---|---|
| 2026-07-04 | 2026-06-01 〜 2026-07-31 |

## スケジュール

freee API枠を手動連携へ優先配分するため、通常取得は毎週土曜2:30に実行する。

| バッチ | 実行時刻 | 目的 |
|---|---|---|
| `FreeeInvoiceImportScheduler` | 毎週土曜2:30 | freee請求をWorkへ取得 |
| `FreeeInvoiceStatusSyncBatch` | 毎日3:00 | 支払期日が前月1日〜当月末の既存請求の送付・決済ステータス同期 |

`FreeeInvoiceStatusSyncBatch` は、freee連携済み・未取消・未決済の請求のうち、Salesforce請求の支払期日が前月1日〜当月末に入るものだけを対象にする。
これにより、過去の未決済請求全件を毎日取得し続けることを避け、freee API消費を抑制する。

## 連携の流れ

1. Salesforceで契約月次明細を先に作成する。
2. freee側で請求書が作成・送付される。
3. Salesforceが前月1日〜当月末のfreee請求を取得する。
4. 取得データを `Mig_FreeeInvoiceWork__c` / `Mig_FreeeInvoiceLineWork__c` に格納する。
5. Work上で取引先、契約管理、契約期間、契約月次明細を解決する。
6. 解決できたWorkを請求・請求明細へ反映する。
7. 契約月次明細から関連請求の送付ステータス・決済ステータスを確認する。

## API上限対策

- 通常取得は前月分と今月分のみ。
- freee請求一覧APIは `page` / `per_page` ではなく、freee請求書API仕様の `limit` / `offset` で取得する。
- 取得開始位置は `offset = (ページ番号 - 1) × 取得件数` で算出する。
- `perPage` は10件に制限する。
- ページ送りは60分間隔にする。
- 1日の取得結果が `perPage` 件と同数の場合は、同じ日付の次ページを必ず取得する。
- 1日の取得結果が `perPage` 件未満になった時点で、その日付の取得完了とする。
- 429が返った場合は、freeeレスポンスの `reset` 時刻を考慮し、短時間で再試行しない。
- 見積連携、請求書作成、取引先同期などの手動操作用API枠を優先する。

## 再発防止ルール

2026-06-20のfreee請求で、`page` / `per_page` 指定が同じ20件を返し続け、21件目以降の請求を取得できない事象が発生した。
同じ事象を避けるため、請求一覧取得では以下を必須とする。

1. 一覧取得は `limit` / `offset` のみを使用する。
2. `offset` を進めたページで取得件数が0件または `limit` 未満になるまで、同一日付の取得を継続する。
3. 取得した一覧のIDをもとに、請求詳細APIをID単位で呼び出してWorkへ保存する。
4. 取り込み後は、freee一覧の件数、Work件数、Salesforce請求件数を照合する。

## 例外対応

過去分の取り込み漏れ、過去請求の修正確認、移行時再取得が必要な場合のみ、手動で任意期間を指定して取得する。
この場合も、業務影響を避けるためfreee API上限の残量を確認してから実行する。
