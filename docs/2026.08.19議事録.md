# Salesforce定例 議事録

## 1. 会議概要

| 項目 | 内容 |
|---|---|
| 会議目的 | 見積・請求、アップセル、CS管理に関する運用課題と実装方針の整理 |
| 対象業務 | 営業、CS、経理、Salesforceシステム管理 |
| 現在の状況 | 実装・開発中 |
| 実装時期 | フェーズ1：本週中、フェーズ2：来週以降 |

## 2. 決定事項

### 2.1 見積テンプレート

- 複数パターンを含む「フルパターンテンプレート」を使用する。
- 見積作成時に不要な項目を削除して利用する。
- フェーズ2では、契約書型テンプレートを追加検討する。

### 2.2 Freeeの自社担当者

- Salesforceの見積所有者を、Freee見積の自社担当者として連携する。
- Freee同期を実行したユーザーではなく、見積所有者を基準とする。
- 請求書についても、自社担当者の設定方法を確認する。

### 2.3 アップセル時の請求処理

当面は、以下の手順で手動対応する。

1. アップセル差額分の見積を作成する。
2. 元の取引から契約管理を特定する。
3. アップセル適用月の既存請求へ差額明細を追加する。
4. 契約管理のプランカテゴリ、アカウント数などを更新する。
5. 契約月次明細とMRRが正しく更新されていることを確認する。

適用月の原則：

- 20日までの申請：当月または合意した適用月に反映
- 20日以降の申請：翌月へ繰り越し
- 顧客固有の例外は個別に確認する

### 2.4 CS管理

- Salesforceの取引・契約管理をCS管理の基礎データとする。
- 既存契約の取引先紐付けは対応済み。
- 月次明細が存在しない有効契約は、別途調査・補完する。

## 3. 要件

### Must

- 複数パターンに対応できる見積テンプレート運用
- Salesforce見積所有者のFreee自社担当者への連携
- アップセル請求を手動で正しく処理できる運用ルール
- 取引・契約管理とCS管理情報の一元化
- 月次明細がない有効契約の特定と補完

### Want

- アップセル請求作成の自動化
- 親取引・契約管理を自動特定する機能
- アップセル差額を既存請求明細へ追加する機能
- 請求明細変更に連動したMRRの自動更新
- アカウント数やプラン情報の自動反映

## 4. 現状課題

| # | 課題 | 業務影響 | 対応方針 |
|---|---|---|---|
| 1 | 見積テンプレートが単一パターン | 見積作成方法が統一されない | フルパターン方式へ統一 |
| 2 | Freeeの自社担当者が意図した担当者にならない | 書類上の担当者が不正確 | Salesforce見積所有者を連携 |
| 3 | 一部の取引が取引先に正しく紐づいていない | CS管理で契約内容を確認できない | 既存データを点検・補完 |
| 4 | 月次明細がない有効契約が存在する | MRRや将来売上が不正確 | 対象を抽出して補完 |
| 5 | アップセル運用がケースごとに異なる | 請求分割や登録ミスが発生 | 運用ルールを統一 |
| 6 | アップセル時の契約情報を手動更新している | アカウント数やMRRに不整合が発生 | 当面手動、将来自動化 |
| 7 | 請求書が分割される場合がある | 顧客クレームにつながる | 既存請求への差額明細追加を原則化 |

## 5. 未確定事項

- アップセル適用月に関する顧客別例外の管理方法

- 請求明細変更時のMRR再計算方法
- 月次明細がない有効契約の補完ルール
- フェーズ2で使用する契約書型テンプレートの内容

## 7. 主要リスク

- アップセル運用が複雑で、特定担当者へ業務が集中している。
- 請求書の分割発行が顧客クレームにつながる可能性がある。
- アカウント数やプラン更新の手作業により、MRRに不整合が生じる可能性がある。
- 既存データの紐付け不足により、CS管理や売上管理の正確性が下がる可能性がある。
